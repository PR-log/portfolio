01 · About

데이터 뒤의 과정을 봅니다

데이터를 모아 분석하는 것을 넘어, AI가 바로 학습할 수 있는 형태로 가공하는 과정에 관심이 있습니다.

생성형 AI와 LLM이 빠르게 발전할수록 모델의 실제 성능은 결국 학습 데이터의 품질이 결정한다는 것을 프로젝트를 진행하며 체감했습니다. 그래서 Data-Centric AI 관점에서 전처리와 데이터셋 구조화를 계속 공부해 왔습니다.

94만 건 규모의 정형 데이터를 전처리하고 예측 모델을 학습시켰고, Ubuntu / GPU 환경에서 학습 파이프라인을 구성해 봤습니다. 팀 프로젝트에서 확률 보정 도입을 함께 논의하며 정확도가 좋아도 예측 확률 자체를 믿을 수 없으면 실무에 쓸 수 없다는 것을 알게 됐고, 이후로는 성능과 함께 결과의 신뢰도를 봅니다.

AI 결과물 뒤의 고된 전처리 과정을 알기에, 눈에 잘 띄지 않는 데이터 품질 작업을 끝까지 파고드는 연구자가 되고 싶습니다.

Data-Centric AI

모델 구조를 바꾸기보다 학습 데이터의 품질·일관성·라벨링 체계를 개선해 성능을 끌어올리는 접근.

웹·이미지·텍스트처럼 정제되지 않은 데이터를 AI가 학습할 수 있는 형태로 바꾸는 파이프라인 설계.

01문제 정의 — 점수의 절반은 '확률이 맞는가'

Score = 0.5 × (1 − AUC) + 0.25 × Brier + 0.25 × ECE낮을수록 좋음

위험군의 순위를 잘 매기는 것(AUC)만으로는 상위권에 갈 수 없는 구조였습니다. "이 사람의 사고 확률은 3%"라고 말했을 때 실제로 그 집단에서 3%가 사고를 내야 좋은 점수를 받습니다. 그래서 목표를 '분류 성능 극대화'가 아니라 '신뢰할 수 있는 확률 추정'으로 잡았습니다.

여기에 사고 위험군이 소수인 클래스 불균형, 그리고 개인의 과거 이력을 쓰는 순간 미래 정보가 새어 드는 데이터 누수 위험이 겹쳐 있었습니다.

  • 모델은 분리, 파생변수는 통합. 신규·유지 검사는 수집 항목과 분포가 달라 모델을 나눴지만, 한 사람의 이력이 두 테이블에 걸쳐 있어 파생변수는 합쳐서 계산했습니다.
  • 범주형 변수는 One-hot 인코딩, 날짜는 연·월로 분해해 시계열 특성을 확보했습니다.
  • 과거 이력이 없는 대상은 −1로 대체. 단순 결측 처리가 아니라 '이력 없음' 자체를 하나의 신호로 보존하기 위한 선택이었습니다.

03학습 최적화 · 제출 파이프라인 구현 담당

  • 클래스 불균형을 보정하고 XGBoost 하이퍼파라미터를 튜닝했습니다.
  • 94만 건에서는 학습 시간 자체가 병목이었습니다. tree_method='hist'로 히스토그램 기반 분할로 바꿔 반복 실험이 가능한 수준까지 효율을 끌어올렸습니다.
  • 학습된 모델에 테스트 데이터를 같은 전처리로 통과시켜 제출 파일까지 만드는 추론 파이프라인을 구성했습니다. 학습 때와 피처 순서가 어긋나지 않도록 컬럼 목록을 저장해 reindex로 맞췄습니다.

04팀과 함께 설계한 부분 설계 논의 참여

아래 두 가지는 구현은 팀원이 맡았고, 저는 설계 논의에 참여했습니다. 프로젝트의 성패를 가른 판단들이라 함께 기록합니다.

데이터 누수 차단

개인 ID 기준 과거 이력 변수를 만들 때 단순 집계를 하면 예측 시점 이후 정보가 섞입니다. groupby + expanding window + shift(1)로 각 시점 이전 정보만 누적되도록 통제했습니다.

확률 보정

기본 모델은 위험 확률을 실제보다 높게 예측하는 과신 경향을 보였습니다. CalibratedClassifierCV(method='isotonic', cv='prefit')로 보정했고, Platt Scaling도 5-fold OOF로 함께 실험했습니다.

여기서 배운 것

구현은 제 손으로 하지 않았지만, "왜 보정이 필요한가"를 팀과 함께 따지면서 분류 성능과 확률 신뢰도는 별개의 문제라는 걸 알게 됐습니다. AUC가 같아도 확률값을 그대로 믿을 수 있는 모델과 없는 모델이 갈립니다. 이후 모델을 만들 때 성능 지표만 보지 않게 된 계기였습니다.

05결과

무엇이 이 차이를 만들었나

공식 베이스라인은 개인 식별자(PrimaryKey)를 학습에서 제외하고 "이번 검사에서 어떤 수치가 나왔나"만 썼습니다. 검사 결과 시퀀스의 평균·표준편차·비율을 정교하게 뽑았는데도 AUC는 0.5 — 거의 무작위였습니다.

개인 ID를 기준으로 과거 검사 이력을 파생변수로 만들자 0.71까지 올랐습니다. 이 문제에서는 "이 검사에서 뭐가 나왔나"보다 "이 사람이 과거에 어땠나"가 훨씬 강한 신호였습니다. 모델이 아니라 무엇을 변수로 볼지를 바꾼 결과입니다.

※ 두 수치는 검증 분할이 서로 다르므로 정밀한 비교는 아닙니다. 다만 격차가 커서 방향성은 분명합니다.

06한계 및 개선점

  1. 전처리 단계에서 검증 설계를 함께 보지 못함피처를 만드는 데 집중하느라 train/validation 분할은 무작위로 두었습니다. 검사 시점 기준의 time-based split을 제안했다면 실제 운영 환경에 더 가까운 검증이 되었을 것입니다.
  2. 클래스 불균형 처리 비교 부재가중치 보정만 적용했고, SMOTE 같은 리샘플링 기법과의 비교는 하지 못했습니다.
  3. 범주형 인코딩의 일관성추론 단계에서 LabelEncoder를 테스트 데이터에 다시 fit하는 구조라, 학습 때와 인코딩이 어긋날 여지가 있었습니다. 인코더를 저장해 재사용했어야 합니다.
  4. 보정 전 baseline을 남기지 않음코드가 보정 후 성능만 출력하도록 작성되어 있어, 보정으로 얼마나 좋아졌는지 정량화할 수 없습니다. 이후로는 어떤 처리를 적용하기 전에 baseline부터 남깁니다.

03한계 — OCR이 병목입니다

탐지·추적·프레임 선택까지는 안정적이지만, 최종 문자 인식 신뢰도가 0.1~0.7로 낮고 판독 결과가 실제 번호판과 어긋나는 경우가 많습니다.

  1. 해상도 부족원거리 차량의 크롭이 위처럼 수십 픽셀에 불과해 OCR이 문자를 구분하기 어렵습니다.
  2. 범용 OCR 사용번호판 서체·배치에 특화되지 않은 일반 OCR을 썼습니다.
  3. 전처리 부재기울기 보정(perspective transform), 이진화, 대비 향상을 적용하지 않았습니다.
  4. 선명도 기준 미정량화blur score는 상대 비교만 했고, "얼마나 선명해야 읽을 수 있는가"의 임계값은 정하지 못했습니다.

개선한다면 문자를 별도 탐지 클래스로 학습해 문자 단위 인식으로 바꾸거나, 크롭 단계에 super-resolution과 기울기 보정을 넣는 것이 우선이라고 봅니다.

04사후 점검 — 라벨이 지표의 뜻을 바꾼다

목표는 사람 탐지였지만, 학습 라벨을 다시 확인해 보니 사람·승용차·승합차·트럭 등 모든 객체가 하나의 클래스(item)로 합쳐져 있었습니다. 학습 인스턴스 343,201개도 VisDrone 학습셋 10개 클래스 전체의 객체 수와 거의 같습니다.

01개요

Stacked ensemble과 SVM 기반의 NBA 경기 예측 선행 연구 3편을 참고해 방향을 잡았습니다. 저는 데이터 탐색으로 분석 방향을 설계하고, 앙상블을 구성하는 모델 하나를 맡아 개발했습니다.
개인분석 보고서AI 부트캠프 B1

가짜 음성 탐지 모델 분석

공개 Kaggle 노트북(Conformer)을 실행·시연하고, 모델 선택의 타당성과 한계를 분석한 보고서입니다.

직접 구현한 모델이 아닙니다

공개된 노트북을 환경에 맞춰 실행·시연하고, 사용된 모델과 접근법을 기술적으로 분석했습니다. '코드를 어떻게 짰는가'보다 '왜 이 모델이고, 결과를 어떻게 읽어야 하는가'에 초점을 뒀습니다.

01왜 Conformer였나

스펙트로그램은 이미지 형태지만 내용은 음성입니다. ImageNet 사전학습 모델은 음성 특유의 시간–주파수 패턴에 약하므로, 도메인이 맞는 전이학습(LibriSpeech로 사전학습된 ASR 인코더)이 타당하다고 분석했습니다. CNN이 합성 음성의 국소 아티팩트를, Self-Attention이 발화 전체의 문맥을 잡습니다.

02핵심 발견 — 일반화 격차

99.8%Valid F1
61.2%Test F1
100%Test Precision
44%Test Recall

원인은 ASVspoof 데이터셋 구조에 있었습니다. Valid는 학습과 같은 위조 시스템(A01~A06), Test는 본 적 없는 위조 시스템(A07~A19)으로 구성됩니다. 학습한 합성 방식에는 강하지만 새로운 공격에는 취약하다는 뜻입니다.

더 중요한 것은 오류의 종류

Precision 100%, Recall 44% — 오탐은 0이지만 실제 가짜의 56%를 놓칩니다. 보안 관점에서 "가짜를 진짜로 통과시키는" 가장 위험한 오류가 많다는 의미입니다.

03평가지표 비판

이 노트북은 Accuracy·F1로 평가하지만, ASVspoof의 공식 지표는 EER과 min t-DCF입니다. 다른 연구와 비교하려면 공식 지표를 써야 합니다.

04개선 제안

  1. 증강 활성화RawBoost 등 안티스푸핑 전용 증강으로 미지 공격에 대한 일반화를 높입니다.
  2. 프론트엔드 교체고정 Mel-Spectrogram 대신 원형 파형을 직접 다루는 RawNet2 / AASIST, 또는 wav2vec2 / WavLM 자기지도 표현을 씁니다.
  3. 재현율 개선분류 임계값 조정, 손실 가중치 튜닝, score calibration으로 미탐을 줄입니다.
