About

데이터를 모아 분석하는 것을 넘어, AI가 바로 학습할 수 있는 형태로 가공하는 과정에 관심이 있습니다.

생성형 AI와 LLM이 빠르게 발전할수록 모델의 실제 성능은 결국 학습 데이터의 품질이 결정한다는 것을 프로젝트를 진행하며 체감했습니다. 그래서 Data-Centric AI 관점에서 정교한 전처리와 데이터셋 구조화를 계속 공부해 왔습니다.

94만 건 규모의 정형 데이터를 전처리하고 예측 모델을 학습시켰으며, Ubuntu / GPU 환경에서 학습 파이프라인을 구성하는 과정을 경험했습니다. 팀 프로젝트에서 확률 보정 도입을 함께 논의하며 정확도 지표가 좋아도 예측 확률 자체를 신뢰할 수 없으면 실무에 쓸 수 없다는 것을 알게 됐고, 이후로는 성능뿐 아니라 결과의 신뢰도를 함께 보려 합니다.

AI 결과물 뒤에 있는 고된 전처리 과정을 알기에, 눈에 잘 띄지 않는 데이터 품질 작업을 끝까지 파고드는 연구자가 되고 싶습니다.

01 — 문제 정의

이 대회의 평가지표는 다음과 같았습니다.

Score = 0.5 × (1 − AUC) + 0.25 × Brier + 0.25 × ECE
낮을수록 좋음

주목할 점은 확률의 신뢰도를 재는 Brier Score와 ECE가 전체 점수의 50%를 차지한다는 것입니다. 위험군의 순위를 잘 매기는 것(AUC)만으로는 상위권에 갈 수 없고, "이 사람의 사고 확률은 3%"라고 말했을 때 실제로 그 집단에서 3%가 사고를 내야 좋은 점수를 받는 구조였습니다.

그래서 이 프로젝트의 목표를 "분류 성능 극대화"가 아니라 "신뢰할 수 있는 확률 추정"으로 설정했습니다. 여기에 더해, 사고 위험군은 전체의 소수에 불과한 클래스 불균형 상태였고, 개인의 과거 이력을 변수로 사용하는 순간 미래 정보가 학습에 새어 들어가는 데이터 누수(Data Leakage) 위험이 컸습니다.

02 — 데이터 설계 · 전처리 담당
데이터셋규모설명
train_df944,767 행전체 검사 이력
train_A_detail647,241 행 × 37 열신규 검사 상세
train_B_detail297,526 행 × 31 열유지 검사 상세

신규 검사와 유지 검사는 수집 항목과 분포가 달라 모델은 분리해 학습하되, 파생변수 생성은 통합했습니다. 한 사람의 이력이 두 테이블에 걸쳐 있어서, 합치지 않으면 과거 이력을 온전히 계산할 수 없기 때문입니다.

범주형 변수는 One-hot 인코딩, 날짜는 연·월로 분해해 시계열 특성을 확보했습니다.

과거 이력이 없는 대상은 −1로 대체했습니다. 단순한 결측 처리가 아니라, '이력 없음' 자체를 하나의 신호로 보존하기 위한 선택이었습니다.

03 — 학습 최적화 · 제출 파이프라인 담당

사고 위험군이 전체의 소수인 클래스 불균형을 보정하고, XGBoost 하이퍼파라미터를 튜닝했습니다.

94만 건 규모에서는 학습 시간 자체가 병목이었습니다. tree_method='hist'를 적용해 히스토그램 기반 분할로 바꾸면서 반복 실험이 가능한 수준까지 학습 효율을 끌어올렸습니다.

학습된 모델을 불러와 테스트 데이터에 동일한 전처리를 적용하고 제출 파일까지 생성하는 추론 파이프라인을 구성했습니다. 학습 때와 추론 때 피처 순서가 어긋나지 않도록 컬럼 목록을 저장해 reindex로 맞추는 방식을 썼습니다.

04 — 팀과 함께 설계한 부분 설계 논의 참여

아래 두 가지는 구현은 팀원이 맡았고, 저는 설계 논의에 참여했습니다. 이 프로젝트의 성패를 가른 판단들이라 함께 기록합니다.

데이터 누수 차단 — 개인 ID 기준으로 과거 검사 횟수·위험 이력 파생변수를 만들 때, 단순 집계를 하면 예측 시점 이후의 정보가 섞입니다. groupby + expanding window + shift(1) 조합으로 각 시점에서 그 이전까지의 정보만 누적되도록 통제했습니다.

확률 보정 — 기본 모델은 위험 확률을 실제보다 높게 예측하는 과신 경향을 보였습니다. CalibratedClassifierCV(method='isotonic', cv='prefit')로 보정했고, Platt Scaling도 5-fold OOF 방식으로 함께 실험해 비교했습니다.

여기서 배운 것 — 구현은 제 손으로 하지 않았지만, "왜 보정이 필요한가"를 팀과 함께 따지는 과정에서 분류 성능과 확률 신뢰도가 별개의 문제라는 것을 알게 됐습니다. AUC가 같아도 확률값을 그대로 신뢰할 수 있는 모델과 없는 모델이 갈립니다. 이후 제가 모델을 만들 때 성능 지표만 보지 않게 된 계기였습니다.

팀 모델XGBoost · 개인 이력 파생변수0.71420.7070

무엇이 이 차이를 만들었나
공식 베이스라인은 개인 식별자(PrimaryKey)를 학습에서 제외하고 "이번 검사에서 어떤 수치가 나왔나"만 사용했습니다. 검사 결과 시퀀스의 평균·표준편차·비율을 정교하게 뽑았음에도 AUC가 0.5 — 거의 무작위 수준이었습니다.

반면 개인 ID를 기준으로 과거 검사 이력을 파생변수로 만들자 AUC가 0.71까지 올랐습니다. 즉 이 문제에서는 "이 검사에서 뭐가 나왔나"보다 "이 사람이 과거에 어땠나"가 훨씬 강한 신호였습니다. 모델을 바꾼 것이 아니라 무엇을 변수로 볼 것인가를 바꾼 결과입니다.

※ 두 수치는 검증 분할이 서로 다르므로 정밀한 비교는 아닙니다. 다만 격차가 커서 방향성은 분명합니다.

변수 중요도 분석 결과 과거 위험 이력과 고연령대 변수가 예측에 가장 크게 기여했습니다.

06 — 한계 및 개선점

전처리 단계에서 검증 설계를 함께 보지 못함 — 제가 담당한 전처리는 피처를 만드는 데 집중했고, train/validation 분할은 무작위로 두었습니다. 검사 시점 기준의 time-based split을 제안했다면 실제 운영 환경에 더 가까운 검증이 되었을 것입니다. 전처리 담당자가 검증 설계까지 함께 고민해야 한다는 걸 뒤늦게 알았습니다.

클래스 불균형 처리 비교 부재 — 가중치 보정만 적용했고, SMOTE 등 리샘플링 기법과의 비교 실험은 수행하지 못했습니다.

범주형 인코딩의 일관성 — 추론 단계에서 LabelEncoder를 테스트 데이터에 다시 fit하는 구조라, 학습 때와 인코딩이 어긋날 여지가 있었습니다. 인코더를 저장해 재사용하는 방식이 옳았습니다.

보정 전 baseline을 남기지 않음 — 코드가 보정 후 성능만 출력하도록 작성되어 있어, 보정으로 무엇이 얼마나 좋아졌는지 정량화할 수 없습니다. 비교 대상을 먼저 기록해두는 것이 실험의 기본인데 그 습관이 없었습니다. 이후로는 어떤 처리를 적용하기 전에 baseline부터 남깁니다.

VisDrone 항공 영상 사람 탐지 개인 프로젝트

영상처리 수업 프로젝트. 과제 조건은 "주어진 이미지를 인식하는 모델을 만들 것" 뿐이었고, 데이터셋 선정 · 클래스 재설계 · 모델 선택 · 학습 전략을 모두 직접 결정했습니다.

클래스 재설계 — VisDrone2019-DET의 10개 클래스 중 pedestrian(보행 중)과 people(그 외 자세)을 하나의 person 클래스로 병합했습니다. 자세 차이만으로 라벨이 갈리면 학습이 불안정해지고, 목적상 구분할 이유도 없다고 판단했습니다.

해상도 판단 — 항공 영상의 사람은 화면에서 매우 작게 나타납니다. 기본값 640에서는 다운샘플링 과정에 특징이 사라진다고 보고 imgsz를 960으로 올려 학습했습니다. 멀티 GPU, 100 에폭, 약 4.9시간이 소요됐습니다.

NBA 이주의 선수 예측 개인 프로젝트

NBA "이주의 선수(Player of the Week)"를 예측하는 문제. 농구 지식이 거의 없는 상태에서 시작했기 때문에, 오히려 도메인 지식 없이 지표만으로 선정 기준을 역추론할 수 있는지를 목표로 잡았습니다.

가설 — 이주의 선수는 모두 평균 득점 상위권이라는 관찰에서 출발해, "득점 + 팀 승리 + 경기 영향력"이 선정 기준일 것이라는 가설을 세우고 W, GP, PTS, REB, AST, FP, +/− 를 변수로 선정했습니다.

모델 선택 과정 — 로지스틱 회귀로 시작해 상위 2~5위 내 예측에 성공했습니다. 성능을 더 높이려 XGBoost를 적용했으나 데이터를 늘릴수록 성능이 하락했고, 표본이 적어 생긴 과적합으로 판단해 파라미터를 조정했지만 개선되지 않았습니다. 결국 단순한 모델로 되돌아왔습니다.

분포 차이 발견 — 초기 정확도 문제가 모델 탓이 아니라 동부·서부 데이터 분포 차이 때문일 가능성을 의심해 컨퍼런스를 분리 학습했고, 그 결과 양쪽 모두에서 정확한 예측이 가능해졌습니다.

실패 분석 — 서부 예측이 빗나갔습니다. 나중에 같은 사이트에서 데이터를 다시 받아 모델을 돌리니 정답(르브론 제임스)이 1위로 나왔습니다. 예측 등록 직전에 실행했는데 그 시점까지 당일 경기 기록이 사이트에 반영되지 않았던 것이 원인이었습니다. 모델이 아니라 데이터 수집 시점의 문제였습니다.

동부에서는 모델이 Brandon Ingram을 가장 많이 지목했는데, 주변 조언을 듣고 다른 선수로 바꿔 제출해 틀렸습니다. 실제 정답은 Brandon Ingram이었습니다. 근거 있는 예측을 스스로 신뢰하지 못한 것이 가장 큰 아쉬움입니다.

해석 — SHAP waterfall plot으로 변수 기여도를 분석했습니다. FP(판타지 포인트)가 +1.23으로 가장 크게 기여했고, +/−(+0.45)와 승리 수(+0.37)가 뒤를 이어, 모델이 개별 기록뿐 아니라 팀 성과와 경기 영향력을 함께 반영하고 있음을 확인했습니다.

결론 — 단순 모델도 충분히 강력하다는 것, 데이터 분리가 모델 선택보다 중요할 수 있다는 것, 그리고 모델 이전에 데이터 전처리와 수집 시점이 결과를 좌우한다는 것.

가짜 음성 탐지 모델 분석 개인 · 분석 보고서

※ 직접 구현한 모델이 아니라, 공개된 Kaggle 노트북(Conformer 기반)을 실행·시연하고 모델 선택의 타당성과 한계를 분석한 보고서입니다.

왜 Conformer였나 — 스펙트로그램은 이미지 형태지만 내용은 음성입니다. ImageNet 사전학습 모델은 음성 특유의 시간–주파수 패턴에 약하므로, 도메인이 맞는 전이학습(LibriSpeech로 사전학습된 ASR 인코더)이 타당하다고 분석했습니다. CNN이 합성 음성의 국소 아티팩트를, Self-Attention이 발화 전체 문맥을 잡습니다.

핵심 발견 — 일반화 격차
Valid F1 99.8% → Test F1 61.2%. 원인은 ASVspoof 데이터셋 구조에 있었습니다. Valid는 학습과 같은 위조 시스템(A01~A06), Test는 본 적 없는 위조 시스템(A07~A19)으로 구성됩니다. 학습한 합성 방식에는 강하지만 새로운 공격에는 취약하다는 뜻입니다.

더 중요한 건 오류의 종류입니다. Test에서 Precision 100%, Recall 44% — 오탐은 0이지만 실제 가짜의 56%를 놓칩니다. 보안 관점에서 "가짜를 진짜로 통과시키는" 가장 위험한 오류가 많다는 의미입니다.

평가지표 비판 — 이 노트북은 Accuracy·F1로 평가하지만, ASVspoof의 공식 지표는 EER과 min t-DCF입니다. 타 연구와 비교하려면 공식 지표를 써야 합니다.

개선 제안 — RawBoost 등 안티스푸핑 전용 증강 활성화, 고정 Mel-Spectrogram 대신 원형 파형을 직접 다루는 RawNet2 / AASIST 또는 wav2vec2 / WavLM 자기지도 표현으로 프론트엔드 교체.
